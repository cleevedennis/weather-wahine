# Architecture

Weather Wahine is a static, dependency-free web page. There is no build step and no server: the browser loads
`index.html` and `tides-data.js` and calls the Open-Meteo APIs directly.

## Files

| File | Role |
|---|---|
| `index.html` | Everything the user sees: HTML, CSS (in `<style>`) and the app script (in `<script>`) |
| `tides-data.js` | `window.LINZ_TIDES` — LINZ Onehunga high/low waters, generated by `tools/linz_to_js.py` |
| `data/Onehunga_<year>.csv` | Raw LINZ CSVs, kept so the bundle can be rebuilt and back-tested |
| `manifest.webmanifest` | Home Screen app: name and short name *Weather Wahine*, colours, standalone display, icons |
| `sw.js` | Service worker: offline support |
| `icons/` | `icon.svg` source and rendered PNGs (180 Apple touch, 192, 512, 512 maskable, 32 favicon) |

`tides-data.js` is a plain script (not fetched JSON) so the page also works when opened from disk (`file://`).

## Data flow

```
                 ┌───────────────────────── fetchData(loc) ─────────────────────────┐
 Open-Meteo      │ forecast API: daily summary + hourly code/temp/rain/cloud        │
 (per beach)     │ marine API:  hourly wave_height (+ sea_level_height_msl if model) │
                 └───────────────────────────────┬──────────────────────────────────┘
                                                 │ { loc, weather, marine }
 tides-data.js ──► tideData() ── LINZ (linzTides) or model (findHighTides)
                                                 │ { highs, time, level, source }
                                                 ▼
                                   analyse() → state.days[16]
                                                 │
            renderHero · renderBest · renderTide · renderCal · renderList · toICS
```

`update(force)` drives it: fetch, analyse, render. Forecasts are cached per beach in `state.cache` for an hour.
Changing a setting re-runs `analyse` on cached data; Refresh re-fetches.

The picker remembers the last beach (saved with the settings in `localStorage`; an unknown value, such as the
retired "All beaches", falls back to `DEFAULT_LOC`). Each beach is fetched on its own when first picked.

## Tide sources

`tideData()` picks one per beach:

- **LINZ** when `usesLinz(loc)` — the beach has `linz.hw` set and `tides-data.js` is loaded. `linzTides()` shifts every
  Onehunga high water by `linz.hw` minutes and every low water by `linz.lw` (or `hw` if `lw` is null), then builds a
  20-minute curve by cosine interpolation between consecutive extremes. The marine API is then only asked for waves.
- **Model** otherwise — `findHighTides()` finds local maxima in Open-Meteo's hourly `sea_level_height_msl` and
  refines each with a parabola through the three surrounding hours.

Times are handled as "naive" local minutes (`naive()` / `naiveIso()`): LINZ and Open-Meteo both give NZ local time,
so offsets are plain minute arithmetic and daylight-saving changes need no special handling. See [Tides](tides.md).

## Rules (in `analyse()`)

For each forecast date:

| Field | Rule |
|---|---|
| `highs` | High tides on that date |
| `inWindow` / `tide` | Highs with `from ≤ time ≤ to` (both ends inclusive) |
| `hasTide` | At least 80% of the day's tide curve is available |
| Window hours | Hours that overlap the window: an hour starting at `m` counts if `m + 59 ≥ from` and `m ≤ to` (11:00–16:00 → 11am…4pm hours) |
| `winCode`, `winTemp`, `winRain` | Worst weather code, warmest temperature and highest rain chance in the window hours |
| `hourly` | Whether hourly data was available; if not, the daily summary is used instead |
| `sunny` | `winCode ≤ 2` and `winTemp ≥ minTemp` and (`winRain` missing or `< MAX_RAIN` (40)) |
| `wave` / `bigSwell` | Highest wave height in the window; `bigSwell` when `≥ BIG_SWELL_M` |
| `both` | `tide && sunny` (shown as ★ Tide & sun) |

`settings()` reads the inputs with fallbacks (11:00, 16:00, 22, 30) and swaps a reversed window.

## Configuration (top of the script)

| Constant | Default | Purpose |
|---|---|---|
| `ALL_LOCATIONS` | 6 beaches | Name, coordinates, `harbour` flag, `linz: { hw, lw }` offsets (minutes vs Onehunga) |
| `DEFAULT_LOC` | `"Piha"` | Beach shown first / fallback for unknown saved values |
| `DAYS` | `16` | Forecast length requested from Open-Meteo |
| `BIG_SWELL_M` | `2.5` | Wave height (m) that triggers the swell warning |
| `TZ` | `Pacific/Auckland` | Time zone for API requests and the calendar export |

The picker shows every beach in `ALL_LOCATIONS`, grouped by `group`. Harbour beaches without a LINZ offset
(`tidesPending()`) skip the marine feed and return tide source `pending`: weather only, tides marked "not set up yet".

## State and storage

- `state` — `{ data, key, days, sel, tideSource, fetchedAt }` in memory.
- `localStorage["ww-prefs"]` — beach (by name) and settings. All access is wrapped in `try/catch`; the page works
  without it. Older saves that stored a list position fall back to Piha.

## Rendering & behaviour

- Sky colours follow the selected day's window weather via `body[data-sky]` (clear / partly / overcast / rain / storm).
- Tapping any `[data-i]` element (calendar cell, list row, best-day row) calls `select(i)`; they are keyboard-focusable
  (`tabindex=0`, `role=button`, Enter/Space).
- On `visibilitychange`, if data is over an hour old or from a previous day, the page re-fetches (home-screen apps
  resume old pages).

## Home Screen app and offline (`sw.js`)

Registered from `index.html` when served over http(s) (not from `file://`). One cache, named by `VERSION`.

| Request | Strategy |
|---|---|
| App files (same origin) | Network first with a 3 s timeout; cached copy if offline or slow. Pre-cached on install. |
| Open-Meteo forecast / marine | Network first with a 6 s timeout. Each good response is stored per URL (one per beach) with an `sw-fetched-at` header; that copy is served when offline. |

If the network is slower than the timeout, the cached copy is shown and the network request still finishes in the
background to refresh the cache. `fetchData()` reads `sw-fetched-at` (`data.savedAt`); `update()` then shows the
yellow *Offline — showing the forecast saved …* status and drops days before today (`todayNZ()`), so an old copy still
starts at the real "Today".

Bump `VERSION` in `sw.js` when the list of pre-cached files (`SHELL`) changes; ordinary edits to `index.html` reach
users anyway because app files are fetched network-first.

## Calendar export (`toICS`)

iCalendar 2.0 with a `Pacific/Auckland` `VTIMEZONE`, stable `UID`s (`<date>-<beach>@weather-wahine`) so re-imports
update events, and lines folded to 75 bytes by `foldLine()`.

## External services

| Service | Endpoint | Used for |
|---|---|---|
| Open-Meteo Forecast | `api.open-meteo.com/v1/forecast` | Daily + hourly weather |
| Open-Meteo Marine | `marine-api.open-meteo.com/v1/marine` | Wave height; model tides (`cell_selection=sea`) |

LINZ files are not fetched by the page (LINZ sends no CORS headers); they are bundled.
